## Fix Phase 1a INFEASIBLE Status

**Root Cause:** 
Phase 1a (timeslot-only CP-SAT) is returning `INFEASIBLE` because `addDailyLessonCapConstraints` is using `maxLecturerConsecutiveHours` (default 4) as the absolute daily lesson limit per lecturer. This is far too restrictive — many lecturers legitimately teach 6-8 lessons on certain days. By capping them at 4 total lessons per day across the whole university, the timeslot assignment becomes mathematically impossible.

**The Fix:**
Remove the `addDailyLessonCapConstraints` call from Phase 1a entirely. 

Max consecutive hours is a fine-grained scheduling/sequencing constraint. It does not belong in the coarse timeslot-assignment phase. Timefold (Phase 2) will handle it as a soft constraint when optimizing the schedule. Phase 1a should only enforce the hard structural constraints:
1. Lecturer no-overlap
2. Student group no-overlap
3. Same course not on same day
4. Special events
5. Lecturer unavailability
6. Lunch breaks

**Changes:**
- `src/main/java/com/university/timetable/service/HybridCpSatSolverService.java`: Delete the `addDailyLessonCapConstraints(...)` call in `runCpSatTimeslotOnly` (around lines 380-383) and add a comment explaining that consecutive hours are handled by Timefold Phase 2.
- Recompile and verify Phase 1a successfully returns a `FEASIBLE` timeslot assignment.
