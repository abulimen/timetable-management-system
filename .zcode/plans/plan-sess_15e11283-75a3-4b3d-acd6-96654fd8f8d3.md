### Solution 1: Adaptive Multi-Objective Weighting (Custom Code)

**File:** `src/main/java/.../solver/AdaptiveConstraintProvider.java`

Create a wrapper around TimetableConstraintProvider that:
1. Tracks hard violation count over recent moves (sliding window)
2. Calculates dynamic weight ratio: `ratio = 1.0 - (hard_violations / max_possible)`
3. Adjusts soft penalty weights: `soft_weight *= (0.5 + ratio * 0.5)`
4. When hard violations are high: soft weights are weak (focus on hard)
5. When hard violations approach zero: soft weights strengthen (focus on quality)

**Implementation approach:**
- Extend `ConstraintProvider` interface
- Wrap the existing `TimetableConstraintProvider`
- Override `defineConstraints()` to apply dynamic weights
- Use a `ScoreDirector` listener to track violation counts
- Maintain a rolling window of last 100 moves for gradient calculation

**Key methods:**
```java
public class AdaptiveConstraintProvider implements ConstraintProvider {
    private final TimetableConstraintProvider wrapped;
    private final AtomicInteger hardViolationCount = new AtomicInteger(0);
    private final int maxPossibleViolations = 1832 * 10; // estimate
    
    @Override
    public Constraint[] defineConstraints(ConstraintFactory factory) {
        double ratio = 1.0 - ((double) hardViolationCount.get() / maxPossibleViolations);
        double softMultiplier = 0.5 + ratio * 0.5; // 0.5 to 1.0
        
        // Get base constraints from wrapped provider
        Constraint[] baseConstraints = wrapped.defineConstraints(factory);
        
        // Apply soft weight multiplier to soft constraints
        return applySoftWeightMultiplier(baseConstraints, softMultiplier);
    }
}
```

**Integration:**
- Modify `SolverConfig` to use `AdaptiveConstraintProvider` instead of `TimetableConstraintProvider`
- Add a `ScoreDirectorListener` to update `hardViolationCount` after each move
- Configure max possible violations based on problem size
